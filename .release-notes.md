**Breaking changes**
- Credential storage now fails closed when the OS keychain is unavailable. An unreachable credential store previously fell back to writing the credential into the config file in plaintext with a warning; that fallback is gone, and the command now exits with a `Keychain unavailable` error having stored nothing. Headless machines, containers, and CI runners are the blast radius: a first `gcx login` there now fails where it used to succeed. Set `GCX_KEYCHAIN=off` (the only accepted value) to opt in to a plaintext write, which is now the only path that produces one. A locked, as opposed to absent, keychain already failed closed and is unchanged (#1271)
- Fleet Management now reaches its API through the `grafana-collector-app` plugin proxy, with no fallback to the old direct path. A grafana.com Cloud Access Policy token carrying `fleet-management:read` or `fleet-management:write` no longer authenticates `gcx fleet` or `gcx instrumentation`; a Grafana stack login plus the enabled collector app is now enough, and `gcx cloud login` is no longer needed for Fleet. A stack token minted before `grafana-api:write` existed returns HTTP 403 because Fleet RPCs are POST, so run `gcx login` again to replace it. Permission follows the matched plugin route rather than the intent of the command: named routes need `grafana-collector-app:read`, wildcard routes need the Admin role or `grafana-collector-app:admin`, and some read-only commands, `tenant get-limits` among them, match wildcard routes. `gcx setup status` reports the plugin state and both route actions, and exits 1 when the plugin is missing or disabled (#1261)
- `gcx synthetic-monitoring probes deploy` emits different manifests, and the probe token has moved out of the Deployment. The generated manifests now create the target Namespace, set the API server address, disable the service account token mount, and read the token from a Kubernetes Secret through `SM_AGENT_API_TOKEN` rather than passing it in the container arguments, so regenerate and re-apply, and update anything that read the token out of the Deployment arguments. The default agent image now tracks `latest` so a new pod picks up current agent fixes; a running pod still needs a restart or rollout to move to a newer image. `--token` keeps working but is deprecated and hidden from help (#1262)
- `gcx synthetic-monitoring probes reset-token` now returns the new token instead of only confirming the reset. The result carries the `gcx.synth.probe_token_reset` schema and includes the token in text, JSON, YAML, and agent output, so anything parsing the previous result shape needs updating (#1262)
- `gcx irm oncall schedules list-final-shifts` takes a `--timezone` flag and no longer sends the timezone of the host. It previously sent the host zone, which is the literal string `Local` on any host that does not set `TZ`, and the API rejects that, so the command could not succeed there at all. Without the flag it now uses the timezone of the schedule, falling back to UTC with a warning on stderr. On a host that did work, one with `TZ` set to an IANA name, the default therefore moves from the host zone to the schedule zone, which changes the rendered shift boundaries; pass `--timezone` to pin them (#1187)
